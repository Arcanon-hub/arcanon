## v1 Requirements

Requirements for the v0.1.9 milestone. Each maps to a roadmap phase.

### Shadow Removal

- [x] **RM-01**: `/arcanon:shadow-scan` no longer exists — `commands/shadow-scan.md` is deleted and the command is absent from the plugin's command surface.
- [x] **RM-02**: `/arcanon:promote-shadow` no longer exists — `commands/promote-shadow.md` is deleted and the command is absent from the plugin's command surface.
- [x] **RM-03**: `/arcanon:diff` no longer accepts `--shadow` — `diff.md` documents only scan-version comparison, and `cmdDiff` no longer branches on `--shadow`.
- [x] **RM-04**: Shadow worker machinery is removed — `getShadowQueryEngine` (`worker/db/pool.js`), `cmdPromoteShadow` + the `"promote-shadow"` HANDLERS entry (`worker/cli/hub.js`), and the live-vs-shadow resolution branch in the diff engine — while the shared `diffScanVersions` / scan-version engine used by `/arcanon:diff <scanA> <scanB>` is preserved intact.
- [x] **RM-05**: `scripts/hub.sh` no longer dispatches `promote-shadow`, and no shell/lib script references the shadow workflow.
- [x] **RM-06**: No dangling references to `shadow-scan`, `promote-shadow`, `--shadow`, `impact-map-shadow.db`, or `getShadowQueryEngine` remain anywhere in plugin source, scripts, skills, or tests (CSS `box-shadow` in the UI is unaffected and explicitly out of scope).

### Rescan Repair

- [x] **FIX-01**: `/arcanon:rescan <repo>` runs end-to-end — its Step-1 inline `node` imports the `node:sqlite` adapter (`worker/db/sqlite-adapter.js`) instead of the removed `better-sqlite3`, and resolves the target repo without `ERR_MODULE_NOT_FOUND`.

### Documentation

- [x] **DOC-01**: The root `README.md` and `plugins/arcanon/README.md` no longer list `/arcanon:shadow-scan`, `/arcanon:promote-shadow`, or `/arcanon:diff --shadow`; the `/arcanon:correct` → `/arcanon:rescan` workflow remains documented and accurate.
- [x] **DOC-02**: `docs/commands.md` reflects the reduced command set — shadow commands removed, remaining commands accurate.
- [x] **DOC-03**: `CHANGELOG.md` has a `[0.1.9]` entry with a `### BREAKING` block naming the three removed commands and the migration path (use `/arcanon:map`'s confirm gate to preview, `/arcanon:diff <scanA> <scanB>` to compare scans).

### Test Coverage

- [x] **TST-01**: A regression test executes the `/arcanon:rescan` Step-1 inline-`node` path against a fixture DB so a future dependency rename fails CI instead of breaking silently (closes the root cause behind both the `deep.md` and `better-sqlite3` silent breakages).
- [x] **TST-02**: A guard test asserts `/arcanon:shadow-scan` and `/arcanon:promote-shadow` command files are absent and that `diff.md` does not mention `--shadow` (regression guard against reintroduction).
- [x] **TST-03**: The full bats suite and worker test suite pass with all removals applied (no orphaned tests, no broken assertions).

### Release Gate

- [x] **VER-01**: All manifests are pinned to `0.1.9` — `plugins/arcanon/package.json`, `plugins/arcanon/.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json` — with the lockfile regenerated via npm.
- [x] **VER-02**: Release gate passes — bats + node suites green, zero shadow references remain (RM-06), and the `CHANGELOG [0.1.9]` section is pinned.

## Inserted Phases (issue-driven, added mid-milestone)

These families were added when phases 131-134 were inserted to fix four GitHub issues
discovered during the milestone. Each family is complete and integration-verified
(see `.planning/v0.1.9-MILESTONE-AUDIT.md`); per-requirement detail lives in the linked
issue and the phase PLAN/SUMMARY frontmatter.

### Protocol Vocabulary — Phase 131 ([#42](https://github.com/Arcanon-hub/arcanon/issues/42))

Render every edge protocol (pub/sub, DB, GraphQL, SSE) through a single canonical
bucket vocabulary (`rest·grpc·events·db·internal·sdk` + infra + `other`) with
fallback-not-reject and persist+read-time normalization via `canonicalProtocol()`.

- [x] **PV-01..06** (131-01): canonical bucket vocabulary + alias map + persist-time normalization; `worker/ui/modules/protocol.js` as the single source of truth.
- [x] **PV-07..10** (131-02): UI render set, edge colors, filter toggles, and agent-prompt vocabulary aligned to the canonical buckets; drift test.
- [x] **PV-11** (131-01): base-path resolution preserved through canonicalization.
- [x] **PV-12..18** (131-03): cross-cutting normalization at every read seam (query-engine, graph API), `other`-never-drop guarantee, regression coverage.

### detectMismatches Parameterized Routes — Phase 132 ([#43](https://github.com/Arcanon-hub/arcanon/issues/43))

Stop false `endpoint_not_exposed` mismatches on parameterized routes.

- [x] **DM-01**: two-sided `canonicalizePath()` (`{...}`→`{_}`) on both consumed and exposed paths in `detectMismatches()`.
- [x] **DM-02**: restrict mismatch detection to HTTP-style protocols via `c.protocol IN ('rest','grpc')` — `events`/`db`/infra buckets are excluded (no exposed_endpoints concept).
- [x] **DM-03**: regression suite for parameterized-route + non-HTTP-protocol exclusion (`query-engine-mismatch-params.test.js`).

### Scanner Backing-Service Client Detection — Phase 133 ([#45](https://github.com/Arcanon-hub/arcanon/issues/45))

Teach the agent scanner to detect network-datastore/broker client connections
(chromadb/pg/mongodb/redis/etc.) by reasoning, examples-not-allowlist.

- [x] **SC-01..03** (133-01): `agent-prompt-discovery.md` flags backing-service clients by reasoning (non-exhaustive examples, no hardcoded allowlist); `backing_service_deps` candidate field added to discovery output; `agent-prompt-service.md` emits one external connection per backing-service client, call-site-conditioned, ambiguous→`other`.
- [x] **SC-04..07** (133-02): `manager.js buildIncrementalConstraint()` EXCEPTION block permits `backing_service_deps` call-site lookup in unchanged files during incremental scans (closes the chromadb-importer-reachable-without-client_files gap); section-coherent + reachability-contract tests.

### detectMismatches Method-Aware Matching — Phase 134 ([#46](https://github.com/Arcanon-hub/arcanon/issues/46))

Make `detectMismatches()` compare HTTP method, not path-only.

- [x] **MM-01..05** (134-01): exposed set keyed on `(UPPER(method), canonicalPath)` via `exposedByMethod` Map; `normalizeMethod()` helper; case-insensitive method comparison; null-method consumed edges fall back to path-only matching (zero new false positives); #43 protections preserved.
- [x] **MM-06..09** (134-02): cross-AI-review hardening — collision-safe keying (nested `Map<method,Set<path>>` replaces the forgeable space-join / superseded `METHOD_PATH_SEP` delimiter), null/empty/whitespace method handling, and forge-regression tests; no behavior change for valid HTTP data.

## Out of Scope

| Feature | Reason |
|---------|--------|
| `/arcanon:rescan` removal | Load-bearing for the `/arcanon:correct` workflow (applies a staged override to one repo); only repaired, not removed. |
| Removing `/arcanon:diff` scan-version comparison | Only the `--shadow` mode is removed; live scan-version diffing is retained and is the documented replacement for shadow diffing. |
| UI `box-shadow` / `drop-shadow` CSS | Unrelated to the shadow-DB feature; cosmetic styling in `worker/ui/`. |
| Migrating other inline-`node` command blocks | Only `/arcanon:rescan` is in scope; a broader audit of inline-`node` blocks is deferred unless TST-01 surfaces additional breakage. |
